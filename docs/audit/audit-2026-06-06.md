## P1 — High Priority (fix this sprint)

### P1-1: sync README has incorrect CLI command paths

**File:** `dracon-sync/README.md`, lines 120-135

The README shows repair commands as top-level subcommands, but the actual CLI uses nested subcommands under `repair`:

| README shows | Actual CLI |
|--------------|------------|
| `dracon-sync repair-concerns` | `dracon-sync repair concerns` |
| `dracon-sync repair-warns` | `dracon-sync repair warns` |
| `dracon-sync stuck list` | `dracon-sync repair stuck-list` |
| `dracon-sync stuck unstuck <repo>` | `dracon-sync repair stuck-unstuck <repo>` |
| `dracon-sync dual-branch list` | `dracon-sync repair dual-branch-list` |
| `dracon-sync dual-branch repair <repo>` | `dracon-sync repair dual-branch-repair <repo>` |
| `dracon-sync repair-origins` | `dracon-sync repair origins` |

**Fix:** Rewrite the command examples in `dracon-sync/README.md` to use the nested subcommand syntax. AGENTS.md already has the correct paths and can be used as a reference.

### P1-2: sync BLUEPRINT has contradictory "AI Integration" section

**File:** `dracon-sync/BLUEPRINT.md`, lines 180-189

The BLUEPRINT contains a section "## AI Integration (Scribe + AI Bumper)" that claims:
- "dracon-sync has integrated AI for generating commit messages (scribe)"
- "Scribe: AI generates commit subjects from diffs"
- "AI Bumper: AI decides semver bump level"

But line 281 says: `[x] AI scribe removed (was not useful for AI workflows)`

And AGENTS.md states: "AI scribe was removed as AI-generated messages were not useful for AI workflows."

**Fix:** Delete the "AI Integration (Scribe + AI Bumper)" section (lines 180-189) and the related "Features (compile-time)" entries for `scribe` and `ai-bumper` features. Keep the Status item that documents the removal.

### P1-3: dracon-sync has 553 `.unwrap()` calls in production code

**Files:** Top hotspots:
- `dracon-sync/src/sync.rs`: 281
- `dracon-sync/src/standard_files.rs`: 52
- `dracon-sync/src/daemon.rs`: 52
- `dracon-sync/src/release.rs`: 49
- `dracon-sync/src/git/mod.rs`: 34
- `dracon-sync/src/policy.rs`: 24
- `dracon-sync/src/exclude.rs`: 22
- `dracon-sync/src/visibility.rs`: 14

Each `.unwrap()` will panic the daemon if the `Result` is `Err` or the `Option` is `None`. A panic in the sync daemon's main loop will cause it to restart (RestartPreventExitStatus=2 78 means config/arg errors don't restart, but panics do), but it disrupts sync operations.

**Fix:** Convert `.unwrap()` to `.unwrap_or()` or `.unwrap_or_else()` with sensible defaults, or use `?` with proper error propagation. Prioritize the top hotspots (sync.rs, daemon.rs) since these run in the hot path.
