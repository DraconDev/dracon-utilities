## P1 — Critical (fix immediately)

### P1-1: `test-ai` command documented but does not exist

**Files referencing it (6 total):**
- `dracon-sync/README.md:113` — `# Test AI provider connectivity / dracon-sync test-ai`
- `dracon-sync/BLUEPRINT.md:241` — `dracon-sync test-ai   # Test all AI providers`
- `dracon-sync/BLUEPRINT.md:280` — `[x] test-ai command for provider verification`
- `AGENTS.md:518` — `  test-ai          Test AI providers connectivity`
- `AGENTS.md:639` — `dracon-sync test-ai`
- `docs/OPERATIONS.md:179` — `dracon-sync test-ai`

**Reality:** The `Command` enum in `dracon-sync/src/main.rs` has no `TestAi` variant. `grep test.ai\|TestAi\|test_ai dracon-sync/src/main.rs` returns nothing.

This contradicts the v1 audit's positive finding "Deterministic commit messages — No LLM at the commit boundary" — if AI scribe was removed, why does `test-ai` still appear in docs?

**Fix:** Either implement the `test-ai` command (it was part of the AI Configuration flow documented in `docs/OPERATIONS.md` and `AGENTS.md` § AI Configuration) or remove all 6 references.

### P1-2: Broken CLI command paths in 3 docs

The actual CLI uses nested subcommands under `repair`, `config`, and `publish`, but docs show old flat-path forms:

| Doc shows | Actual CLI |
|-----------|------------|
| `dracon-sync repair-concerns` | `dracon-sync repair concerns` |
| `dracon-sync repair-warns` | `dracon-sync repair warns` |
| `dracon-sync repair-origins` | `dracon-sync repair origins` |
| `dracon-sync stuck list` | `dracon-sync repair stuck-list` |
| `dracon-sync dual-branch` | `dracon-sync repair dual-branch-list` |
| `dracon-sync edit-config` | `dracon-sync config edit` |
| `dracon-sync publish` | `dracon-sync publish run` |
| `dracon-sync publish-status` | `dracon-sync publish status` |

**Affected files:**
- `dracon-sync/README.md:120-135` — 7 broken commands
- `AGENTS.md:510-523` — 5 broken commands (repair-concerns, repair-warns, edit-config, dual-branch, repair-origins)
- `docs/OPERATIONS.md:120-121` — 2 broken commands (dual-branch-list, dual-branch-repair)

**Note from v2 audit correction:** The v1 audit declared `AGENTS.md` as the "source of truth" with no drift. That was wrong — AGENTS.md has the same broken commands as the README. The v1 audit's P1-1 fix recommendation ("AGENTS.md already has the correct paths and can be used as a reference") was inverted.

**Fix:** Rewrite all three docs using the actual nested-subcommand syntax. The actual command list is in the `Command` enum in `dracon-sync/src/main.rs`.

### P1-3: sync BLUEPRINT has contradictory "AI Integration" section

**File:** `dracon-sync/BLUEPRINT.md`, lines 180-189

The BLUEPRINT contains "## AI Integration (Scribe + AI Bumper)" that claims:
- "dracon-sync has integrated AI for generating commit messages (scribe)"
- "Scribe: AI generates commit subjects from diffs"
- "AI Bumper: AI decides semver bump level"

But line 281 says: `[x] AI scribe removed (was not useful for AI workflows)`

And `AGENTS.md` states: "AI scribe was removed as AI-generated messages were not useful for AI workflows."

**Fix:** Delete the "AI Integration (Scribe + AI Bumper)" section (lines 180-189) and the related "Features (compile-time)" entries for `scribe` and `ai-bumper`. Keep the Status item that documents the removal.

## P2 — High Priority (fix this sprint)

### P2-1: 10 duplicate crates in Cargo.lock

**File:** `Cargo.lock`

`cargo deny check` reports 10 duplicate crate entries:
- `bech32`, `getrandom`, `hashbrown`, `rustc-hash`, `strsim`, `syn`, `toml`, `toml_datetime`, `toml_edit`, `winnow`

These are likely from mixing `dracon-libs` dependencies with direct dependencies in the workspace's per-binary `Cargo.toml` files. Duplicate crates inflate build time and binary size.

**Fix:** Run `cargo update --workspace` and then `cargo dedupe` (or `cargo tree -d` to identify which binaries pull which versions). Consolidate to a single version where possible.

### P2-2: Unmatched source in deny.toml

**File:** `deny.toml:27`

`https://github.com/DraconDev/dracon-libs` is listed as an allowed source but no crate in the dependency tree is fetched from it. The local `dracon-utilities` workspace depends on the local `../dracon-libs` path, not the Git URL.

**Fix:** Remove the Git URL from `deny.toml` sources section, or replace it with the local path if path-source matching is needed.

### P2-3: 7 unused license entries in deny.toml

**File:** `deny.toml` (lines 39, 48 and others)

`cargo deny check` reports 7 `license-not-encountered` warnings:
- `0BSD`
- `AGPL-3.0`
- `AGPL-3.0-or-later`
- `CC0-1.0`
- `Unicode-3.0`
- `Unicode-DFS-2016`
- `Zlib`

**Fix:** Remove these from the allow list in `deny.toml` since no crate uses them.

### P2-4: Tarpaulin coverage reports are 23 days old

**Files:** `dracon-sync/tarpaulin-report.{json,html}`, `dracon-system/tarpaulin-report.json`, `dracon-warden/tarpaulin-report.json`

Reports are dated May 14, 2026 and cover a previous code structure (10 files for sync, 1 for system, 5 for warden). Current code has 28 .rs files in sync, and many more in system/warden.

**Fix:** Run fresh tarpaulin on all 3 binaries:
```bash
cargo tarpaulin -p dracon-sync --out Html --output-dir coverage/
cargo tarpaulin -p dracon-system --out Html --output-dir coverage/
cargo tarpaulin -p dracon-warden --out Html --output-dir coverage/
```

### P2-5: dracon-sync/note.md is a leftover todo

One-line file: `/home/dracon/Dev/obs-wayland-hotkey/ repo got suddenly delete by the recent commit, fixed it but must investigate`

**Fix:** Either move to `docs/archive/` (if the investigation is still pending) or delete (if resolved).
