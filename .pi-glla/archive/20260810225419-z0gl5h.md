FIX MEDIUM (warden) shipped: whole-file-tag recognition is no longer purely syntactic. The old starts_with_any_secret_tag only checked prefix+suffix shape, so a protected file whose PLAINTEXT merely looked like a tag was (1) returned as-is by the clean-side double-encrypt guard (filter.rs:269/317) and committed UNENCRYPTED silently, and (2) on smudge, decrypt_whole_file_tag surfaced Some(Err) which smudge_with_security propagated, hard-failing checkout/merge (seal_smudge always warned + passed through). Fix in security/src/lib.rs (commits d4d163f + a59db98 on dracon-warden main, all mirrors at HEAD a59db98): starts_with_any_secret_tag now requires the payload to be valid base64 AND decode to the age-encryption.org/v1 magic, so tag-shaped plaintext gets properly whole-file encrypted on clean; decrypt_whole_file_tag returns None (graceful fall-through) for invalid base64 or magic mismatch, reserving Some(Err) for genuine age payloads that fail to unlock; smudge_with_security now matches seal_smudge — a real-but-unlockable tag warns once and passes through raw instead of bricking checkout. Three new tests cover recognition rejection (not-base64, wrong-magic) with real-tag controls, smudge pass-through for both fake shapes AND a genuine age payload encrypted to a key that exists nowhere on the machine, and the clean-side behavior (protected .env with tag-shaped plaintext now produces a real whole-file tag; real tags still pass through unchanged).
