## 2. Security Audit

### ✅ Strengths
- **No `unsafe` blocks** in any production code
- **Secret handling is proper**: `load_secret()` checks env vars first, then `.env` files, with world-writable directory checks
- **IndexLock coordination**: Both sync and warden use `O_EXCL` atomic file creation for `.git/index.lock` — prevents TOCTOU races with git operations
- **Zeroize on drop**: Cryptographic keys use `Zeroize`/`ZeroizeOnDrop` from the `zeroize` crate
- **Age encryption**: Proper use of `age` crate for asymmetric encryption with x25519 keys
- **Systemd hardening**: All services use `ProtectSystem=strict`, `ProtectHome=read-only`, `NoNewPrivileges=true`, `PrivateTmp=true`

### ⚠️ Issues

| Severity | Issue | Location | Recommendation |
|----------|-------|----------|----------------|
| MEDIUM | `unwrap()` in production daemon code for JSON serialization | `daemon.rs:53,61` | Use `.unwrap_or_default()` or proper error handling |
| MEDIUM | `expect("git init failed")` in sync flow | `sync.rs:434` | Should propagate error, not panic |
| LOW | `expect()` calls in visibility module | `visibility.rs:1092` | Should use `?` operator |
| LOW | `secrecy` crate feature `serde` enabled — allows serialization of secrets | `dracon-warden/Cargo.toml` | Ensure secrets are never serialized to disk unencrypted |
| INFO | `ALLOW_V1_FALLBACK` atomic bool allows downgrading encryption | `security/src/lib.rs` | Document when this is safe to enable |

### Command Injection Assessment

All `std::process::Command` calls use the safe builder pattern (no shell interpolation):
```rust
std::process::Command::new("git")
    .current_dir(repo)
    .args(["add", "-A"])
    .output()?;
```

**No command injection vectors found.** Arguments are never interpolated into shell strings.

## 3. Error Handling

### ✅ Strengths
- Consistent use of `anyhow::Result` with `.context()` for error chains
- Most functions properly propagate errors with `?`
- Graceful degradation: missing tools (gh, glab) produce warnings, not crashes

### ⚠️ Issues

| Location | Issue | Impact |
|----------|-------|--------|
| `sync.rs:434` | `expect("git init failed")` — panics if git init fails | Daemon crash |
| `daemon.rs:53,61` | `unwrap()` on JSON ser/de for stuck repo entries | Daemon crash on corrupt JSON |
| `visibility.rs:1092` | `expect()` on JSON parsing after stripping | Daemon crash on malformed API response |
| `sync.rs:68` | `std::thread::spawn` for webhook — no panic guard | Silent thread panic |

### Error Propagation Chain

```
main() → run_daemon() → sync_repo() → stage_commit_and_push() → [git operations]
                                    ↓
                              Any error bubbles up, repo is skipped, daemon continues
```

This is the correct pattern — a single repo failure should not crash the daemon.

## 7. Systemd Services

### ✅ Strengths
- **Defense in depth**: Multiple layers of hardening
  - `ProtectSystem=strict` — read-only filesystem
  - `ProtectHome=read-only` — except whitelisted paths
  - `NoNewPrivileges=true` — no privilege escalation
  - `PrivateTmp=true` — isolated /tmp
  - `SystemCallFilter=@system-service` — syscall allowlist
  - `MemoryMax` / `CPUQuota` — resource limits
- **RestartPreventExitStatus=2 78**: Don't restart on config/argument errors
- **Pre-start cleanup**: Kills stale processes before starting

### ⚠️ Issues

| Severity | Issue | Location |
|----------|-------|----------|
| MEDIUM | `Restart=always` means `systemctl stop` doesn't permanently stop — must `disable` first | All services |
| LOW | `ReadWritePaths` includes `~/.ssh` for sync — broad access | `dracon-sync.service` |
| INFO | NixOS-specific PATH in Environment — won't work on non-NixOS | All services |

## 12. Recommendations

### Priority 1 (Fix Soon)

1. **Replace `expect()`/`unwrap()` in production paths** with proper error propagation:
   - `sync.rs:434` — `expect("git init failed")` → `?` operator
   - `daemon.rs:53,61` — `unwrap()` on JSON → `.unwrap_or_default()` or match
   - `visibility.rs:1092` — `expect()` → `?` operator

2. **Add panic guard to webhook thread** (`sync.rs:68`):
   ```rust
   std::thread::spawn(move || {
       std::panic::catch_unwind(|| {
           // webhook logic
       }).ok();
   });
   ```

### Priority 2 (Improve)

3. **Consider splitting `sync.rs`** (3,100 lines) into:
   - `sync/pull.rs` — pull/merge logic
   - `sync/push.rs` — push/fallback logic  
   - `sync/commit.rs` — staging/commit logic
   - `sync/mod.rs` — orchestration

4. **Update `rand` to 0.9** in dracon-warden (minor API changes, no security impact)

5. **Use SHA256 instead of MD5** in install.sh for binary hash comparison

### Priority 3 (Nice to Have)

6. Clean up stale files: `dracon-ai/` directory, `git.rs.test`, old audit files

7. Add integration test for full daemon loop with mock repos

8. Consider structured logging (e.g., `tracing` crate) instead of `eprintln!`

- **Security is taken seriously** (encryption, IndexLock, systemd hardening)

**No critical security vulnerabilities found.** The codebase is production-ready for its intended use case (personal infrastructure daemons).
