# Goal Prompt

Fix the dracon-utilities CI failure caused by the warden pre-push hook's smudge filter failing to decrypt `[DRACON_SECRET:...]` markers in test source files. The warden's SecretScanner is matching parts of Rust function names as secrets (e.g., `test_restore_rejects_nonexistent_path` contains something that looks like a credential pattern), encrypting them on commit, and then the smudge filter can't decrypt them on checkout. This produces invalid Rust syntax (`fn p[DRACON_SECRET:YWdlLWVuY3J5cHRpb24ub3JnL3Yx...]() {`) and breaks `cargo test --workspace --locked`. The fix is to add `.plaintext` siblings to the 3 affected test files (dracon-warden/src/tests.rs, dracon-warden/src/security/tests/atomic_write_test.rs, dracon-warden/src/security/tests/redos_stress_test.rs) to exempt them from the warden filter, then manually restore the original function names from git history.
