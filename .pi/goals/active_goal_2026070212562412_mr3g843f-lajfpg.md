# Goal Prompt

Eliminate the redundant `/home/dracon/Dev/<name>/` standalone worktrees for the 10 game/hegemon submodules of `dracon-platform`. Change the daemon architecture so it auto-commits + auto-pushes directly from `/home/dracon/Dev/dracon-platform/web/games/<wip|released>/<name>/` (the nested submodule path), and the parent's gitlink advances in lockstep.

**Background**

Current state (per `daemon-standalone-removal-2026-07-01.md`):
- Each game submodule has TWO paths: nested `dracon-platform/web/games/wip/<name>/` (detached) and standalone `/home/dracon/Dev/<name>/` (on main)
- The daemon watches the standalone path; nested path is unwatched
- The detached-on-nested invariant is preserved because git forbids two worktrees of one gitdir on the same branch

User's intent: the nested submodule inside the platform is the canonical location. The standalone at `/Dev/<name>/` is redundant and confusing. The daemon should commit+push from the nested path directly, with the parent's gitlink advancing in lockstep so the platform repo's tree stays consistent.

**Submodule size constraint (operator's earlier point)**

Games must stay as submodules (not as plain tracked files) because:
- Polis/hegemon/etc. have large binary content (PNG sprites, MP3 music)
- Tracked-as-submodule: parent stores 40-byte gitlinks → small .git
- Tracked-as-files: parent stores full content → parent's `.git` blows past github's 2GB pack limit

So the architecture stays submodule-based; only the worktree layout changes.

**Daemon code changes required**

1. `materialize_submodule` (in `dracon-sync/src/sync.rs`): change to make the nested submodule checkout itself be the canonical worktree on `main`, instead of materializing a separate standalone at `/Dev/<name>/`.
2. `shared_submodule_canonical_head_sha` (in `dracon-sync/src/exclude.rs`): currently reads `refs/heads/main` from the shared gitdir. Update to handle the case where the nested worktree IS the one on `main` (the file `refs/heads/main` is the source of truth; the daemon's job is just to keep the parent's gitlink tracking that ref).
3. `is_gitlink_unchanged` (in `dracon-sync/src/exclude.rs`): the comparison `nested_HEAD == parent_gitlink` still works correctly when nested is on main — `git rev-parse HEAD` returns the same SHA as `refs/heads/main` when on main. Verify the comparison logic is path-agnostic.
4. Watch-list change: replace `/Dev/polis` etc. with `/Dev/dracon-platform/web/games/wip/polis` etc. in the daemon's `sync-status.json`.
5. The standalone `/Dev/<name>/` worktree should be removed (after migration) so the daemon is not confused by the dual-worktree layout.
6. End-to-end test: make an edit in `/Dev/dracon-platform/web/games/wip/polis/`, verify daemon auto-commits, auto-pushes to github, and the parent's gitlink advances within 1 cycle (a few minutes).

**Migration plan**

Roll out per-game, one at a time, with each migration independently verifiable:
1. Pick a low-stakes game (e.g. junk-runner, darklord, or neonbreak)
2. Migrate that single game: remove its standalone, switch its nested to main, update daemon watch list, push initial state, end-to-end test
3. After 24h of clean operation, migrate the next game
4. After all games are migrated, remove the now-empty `/Dev/<name>/` paths

This staged approach avoids breaking all 10 games at once if something goes wrong.

**Hard constraints (from AGENTS.md + prior goals)**

- No force-push to repos with >5 commits ahead (`force_push_when_behind = false`)
- No history rewrite via filter-repo
- Commit-all principle: daemon commits all untracked files unless explicitly excluded
- Daemon pipeline must continue working for non-game repos (dracon-platform itself, dracon-utilities, etc.) without regression
- 668+ existing tests must continue to pass
